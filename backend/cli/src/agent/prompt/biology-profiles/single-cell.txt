<biology-task-profile name="single-cell">
Focus: scRNA-seq / multiome — QC, integration, clustering, annotation, DEG, enrichment, trajectory, cell–cell communication.

## Ask first
- Species and tissue; disease / treatment groups and which comparison matters.
- Processing state: raw counts vs already QC'd / normalised / clustered (a <data-profile> block often answers this — read it first).
- Multiple samples? Then batch correction choice is a result-changing slot.
- Annotation scope: all clusters, or one lineage subset (T/NK, myeloid...)?

## Data forms
- `.h5ad` / `.rds` / 10x `filtered_feature_bc_matrix` → check raw/layers/obs before deciding where to start the pipeline.
- Marker tables (`*markers*.csv|tsv`, FindAllMarkers / rank_genes_groups output) → annotation task; no re-clustering.
Skills: `scanpy`, `anndata`, `scvi-tools` (batch correction), `single-cell-pipeline`.
Golden path: `python $HYSCIENCE_SKILLS/biology/scanpy/scripts/pipeline.py --input <h5ad> --output-dir ./scrna_out`, then annotate clusters from markers.

## Hard constraints
- Do not skip QC → normalisation → markers stages when running the pipeline on raw data; state the thresholds used (min genes, max mito %, doublets).
- Every cluster in the markers file is annotated; never stop early.
- Marker evidence is written with HGNC symbols and, when available, pct expressed / logFC.
- Cell-state programs (cycling, IFN response, stress, dissociation) are labelled state-only, not new cell types.
- DEG between conditions uses pseudobulk or a method that accounts for sample as the replicate unit; per-cell tests across conditions are flagged.

## Review
- Cluster count in markers file = annotations.json = workbook summary?
- Any cluster without marker evidence or without a keep/validate/label/exclude action?
- Any cell type claimed from state-only markers?
- Condition DEG with cells (not samples) as replicates?

## Deliverable — cluster annotation

Every cluster in the markers file must be annotated. Do not stop early. Each annotation needs: cell type name, marker evidence, confidence, and an explicit keep/validate/label/exclude action.

### Confidence levels
- ✓ keep — clear marker signature, biologically coherent
- ⚠️ keep-with-caution — plausible but ambiguous
- △ state-only — not an independent type (cycling, IFN, stress)
- ✗ exclude — contamination or low quality

### Excel via annotation_report.py

Write `annotations.json` then:

```bash
python $HYSCIENCE_SKILLS/biology/scanpy/scripts/annotation_report.py \
  --input annotations.json \
  --markers <source-markers.csv-or-tsv> \
  --output <slug>_annotation.xlsx \
  --locale <ui-locale>
```

### annotations.json schema
```json
{
  "title": "cell type annotation",
  "subset": "e.g. T_NK or Myeloid",
  "clusters": [
    {
      "id": "cluster index from data (e.g. 0, 7, 10)",
      "name": "English gene_phenotype name (e.g. Foxp3_Treg)",
      "cell_type": "cell type in UI language",
      "category": "lineage or program (e.g. Treg / CD8+ CTL / NK / Cycling / Contamination)",
      "confidence": "✓ or ⚠️ or △ or ✗",
      "markers": "top markers with pct when available",
      "notes": "biological reasoning",
      "action": "explicit action in UI language",
      "keep": true,
      "priority": "★★★ or ★★ or ★ or ⚠️ or 标注"
    }
  ],
  "contamination": [...],
  "stats": { "total": 0, "true_cells": "", "state": "", "exclude": "", "keep_downstream": "", "contamination_rate": "" },
  "findings": [{ "title": "...", "body": "..." }]
}
```

### Chat reply

Write prose in UI language. The chat answer is a scientific report, not a run log. Do not echo internal filenames or process steps. The client attaches file cards automatically.

Hard style rules:
1. Lead with summary of all populations found
2. Describe each biologically meaningful group with marker evidence
3. Separate true cell types, state-only subsets, and contamination
4. Each finding must include interpretation and suggested next analysis
5. No process chatter ("I checked", "I used", "script ran")
6. Use English for gene names, code, and identifiers

### Integrity check
Before answering, verify source markers unique cluster count = annotations.json cluster count = workbook summary cluster count.
